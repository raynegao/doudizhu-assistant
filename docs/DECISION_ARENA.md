# 决策系统评测与强化（2026-10-18）

本文记录决策层（`src/logic/`）第一次有棋力数据的评测，以及据此做的两项强化。所有数字都来自固定种子的自对弈，不涉及视觉、录屏或真实对手。

## 为什么先评测

截至 10-18 的决策系统是"均匀未知牌抽样 + 固定启发式走子 + 每个候选平均分配样本"的蒙特卡洛基线。它在工程上可靠（不推荐手里没有的牌、给置信区间、区间重叠时标排序不稳定），但从未测过棋力：`make benchmark` 只测吞吐量。004 局真实回放的 16 次决策里 7 次 Top-1/Top-2 区间重叠、5 次只跑完 32–269 组样本。没有自对弈评测，任何"变强"都无法验证。

## 评测框架：`src/logic/arena.py`

- 三个座位各自一个 `GameStateTracker`，同一手动作按各自视角（SELF/RIGHT/LEFT）喂入，所以每个智能体都在生产用的 `ObservableGameState` 上决策（只看自己手牌、余牌、桌面与公开历史），竞技场持有真实手牌并校验每一步合法性，三份状态的余牌每步互相核对，终局三方一致。
- 固定种子发牌（17/17/17 + 3 张给地主，地主按副数轮转，不建模叫分），胜负只记谁先出完，不算炸弹/春天倍数。
- 每副牌打三种配置：**被测方当地主 vs 基线农民**、**基线地主 vs 被测方双农民**、**基线自打（参照）**。报告每种配置的地主胜率与 Wilson 95% 区间，以及按副配对的"相对参照的优势"（同一副牌、同样对手，被测方替换参照方后胜负差的均值 ± 95%）。配对差比单独胜率灵敏得多。
- 智能体：`random`（合法非过牌均匀随机）、`rule`（Phase 1 规则推荐）、`heuristic`（原蒙特卡洛走子策略直接当玩家）、`shaped`（新走子策略直接当玩家）、`monte_carlo`（Phase 4/6 推荐器，每次决策的种子来自对局 RNG，不设墙钟预算，结果可复现）。
- 蒙特卡洛智能体额外记录每次决策 Top-2 区间是否重叠、最佳动作的区间宽度、样本数和合法候选数。
- 入口：`python -m scripts.run_decision_arena --games N --subject ... --opponent ...`；`make arena-smoke`。输出 `report.json` 与逐局 `games.jsonl`。

## 强化一：逐次淘汰分配采样（`allocation=successive_halving`）

原来每个候选平分样本：87 个合法动作先按简单打分剪到 20 个，再各跑 N 组对手牌。逐次淘汰在同样的总预算（N × 候选数）下分 `rounds+1` 轮：每轮所有幸存候选共用同一批新抽的对手牌（公共随机数，均值可直接比较），轮末淘汰较弱的一半，直到剩 `top_k` 个；幸存者最终拿到比均匀分配多数倍的样本。被淘汰的候选仍给出评估但排在幸存者之后，避免早期小样本的"好运"动作越过决赛选手。墙钟预算在任何一轮内到期都能停下，此时幸存者已是样本最多的候选。

## 强化二：按牌型最少手数走子（`rollout_policy=shaped`）

`src/logic/rollout_policies.py::hands_to_finish` 用贪心拆牌估计一手牌还要几手出完（王炸、炸弹、最长飞机/顺子/连对、三张、对子、单张，三张和飞机可带走相应的单张/对子）。`ShapedRolloutPolicy` 在模拟里替三家走子：领牌选残余手数最少的动作，小点数优先，不紧急时不动炸弹/王炸，对方剩 1 张不领单、剩 2 张不领对；跟牌选够压的最小动作，若会把牌型拆坏或要用炸弹就过牌，队友领牌且地主不紧急时过牌；对方剩 3 张以内为紧急，什么都压。直接对弈时它对规则基线和随机基线全面占优，对原启发式作为地主持平、作为农民明显更好（见下表）。

## 结果

所有数字：固定种子 `20261018`，每副牌三种配置，"配对优势"为同一副牌替换参照方后胜负差的均值 [95% 区间]。输出目录 `runs/decision-arena/`（不入库）。

### 基线之间（200 副）

| 被测方 vs 基线 | 当地主配对优势 | 当农民配对优势 |
|---|---|---|
| heuristic vs random | +0.335 [+0.249, +0.421] | +0.295 [+0.215, +0.375] |
| heuristic vs rule | +0.420 [+0.346, +0.494] | +0.035 [−0.038, +0.108] |
| shaped vs random | +0.570 [+0.497, +0.643] | +0.285 [+0.211, +0.359] |
| shaped vs rule | +0.330 [+0.255, +0.405] | +0.120 [+0.050, +0.190] |
| shaped vs heuristic | −0.010 [−0.092, +0.072] | +0.255 [+0.176, +0.334] |
| **现有蒙特卡洛（128 样本、均匀、原走子）vs heuristic** | **+0.240 [+0.177, +0.303]**（地主 177/200） | **+0.515 [+0.446, +0.584]**（对方地主只赢 26/200） |

现有蒙特卡洛明显强于它自己的走子启发式；它每次决策在 7 进程并发下约 1.5–4.3 s，仍远超实时预算 1.5 s 所能完成的样本数。

| 变体 | 当地主配对优势 | 当农民配对优势 | 最佳动作样本数（地主 / 农民） | 最佳动作区间宽度 | Top-2 区间重叠率 |

### 结论与采用的默认值

1. **逐次淘汰在同一候选集上采用**（`allocation=successive_halving`，`LiveLayout` 默认值与示例配置已改）：决赛候选样本 64 → 约 100，区间更窄，胜率不降反升（差异在区间内，不夸大为"显著更强"）。把候选集放宽到 64 个（C、E）会稀释样本，不采用。
2. **新走子策略不设为模拟默认**：作为三家的走子替身，它让蒙特卡洛的地主明显变差（D/E 的地主优势掉到 +0.11/+0.06），农民略好。原因是它比原启发式保守（不紧急不动炸弹、牌型拆坏就过牌），当地主时丢失节奏。它作为直接玩家对规则/随机基线更强，保留为 `rollout_policy=shaped` 选项与评测基线。
3. Top-2 区间重叠率在所有变体里都是 50–60%：多数局面前两名候选本来就接近，这是真实的不确定性；实时 UI 的"排序不稳定"提示仍然必要。

## 学习型策略：接入 DouZero 预训练网络（`src/logic/douzero_*`）

DouZero（快手，Apache-2.0）是用深度蒙特卡洛自对弈训练的斗地主智能体。本项目不引入其包，而是把它的观测编码（`douzero_features.py`，纯 numpy：手牌/他人牌/上一手/各家已出牌的 4×13 计数矩阵、余牌与炸弹数 one-hot、最近 15 手序列；地主 373 维、农民 484 维）和网络（`douzero_policy.py`：LSTM(162→128) + 6 层 512 全连接，层名与官方 state dict 一致）按原始源码逐块重写，并用测试固定形状与顺序。**候选动作仍由本项目规则引擎生成**，网络只给每个合法动作打分、取最高分，所以"不推荐手里没有的牌"的保证不变；模型只在请求 DouZero 智能体时才加载，`src.logic` 的导入仍不依赖 PyTorch。

权重：官方 `douzero_WP`（以胜率为目标训练的版本）三个文件 `landlord.ckpt`、`landlord_down.ckpt`、`landlord_up.ckpt`，放在 `models/douzero/`（不入库）。官方 Google Drive 文件夹对匿名列目录返回 404，实际从两个 Apache-2.0 的 GitHub 镜像（`tianqiraf/DouZero_For_HappyDouDiZhu`、`cyt0125/DouZero_For_Offline_Doudizhu`）各取一份，三份文件 SHA256 两两一致（`132e2647…`、`964720fa…`、`b849ea51…`），与我们的网络定义键完全匹配（各 16 个参数）。推理在 Mac CPU 上 113 个候选约 5 ms。

### DouZero 直接出牌的对局结果（固定种子、配对）

| 被测方 vs 对手 | 当地主配对优势 | 当农民配对优势 | 说明 |
|---|---|---|---|
| douzero vs random（200） | — | — | 未单独跑，下行三项已覆盖更强对手 |
| douzero vs rule（200） | +0.560 [+0.491, +0.629] | +0.300 [+0.233, +0.367] | 当地主 187/200 |
| douzero vs heuristic（200） | +0.175 [+0.104, +0.246] | +0.520 [+0.445, +0.595] | 对手是蒙特卡洛的走子替身本身 |
| douzero vs shaped（200） | +0.215 [+0.146, +0.284] | +0.250 [+0.179, +0.321] | |
| **douzero vs 现有蒙特卡洛**（逐次淘汰、64 样本、20 候选，100 副） | **+0.270 [+0.170, +0.370]**（65/100 对参照 38/100） | **+0.220 [+0.125, +0.315]**（对方地主只赢 16/100） | 直接对局，两边都用生产规则引擎的合法动作 |
| **douzero vs 旧默认蒙特卡洛**（均匀分配、128 样本、20 候选，100 副） | **+0.320 [+0.209, +0.431]**（66/100 对参照 34/100） | **+0.130 [+0.027, +0.233]**（对方地主赢 21/100） | 旧默认不设墙钟预算时的离线强度 |

解读：

- 对启发式基线，DouZero 当地主的优势（+0.18）反而比蒙特卡洛（+0.24）小。原因是这个竞技场里的对手就是蒙特卡洛模拟中使用的走子策略：蒙特卡洛等于"已知对手模型"地在算，这是对它有利的偏置；DouZero 的训练对手是它自己。
- 真正的判据是直接对局：DouZero 在地主和农民两个角色上都明显压过现有蒙特卡洛（两个区间都不含 0），而每次决策只要几毫秒（对比蒙特卡洛的秒级）。
- 因此实时模式提供 `decision_backend=douzero`，默认仍是 `monte_carlo`（仓库不分发权重，缺文件时启动即报错）；UI 把 DouZero 的 (value+1)/2 标为"估值（未校准）"，不给区间。

## 局限

- 对手牌仍是均匀抽样，不利用对手的过牌/出牌行为；胜率是"模拟三家都按走子策略打"的胜率，不是对真实对手的胜率。
- 自对弈基线是本项目自己的启发式，不是人类或强 AI；绝对胜率只能横向比较版本，不能对外宣称棋力等级。
- 实时模式受 1.5 s 墙钟预算约束，逐次淘汰在该预算内的实际样本数与离线数字不同；UI 的区间与"排序不稳定"警告仍然是真实的不确定性来源。
