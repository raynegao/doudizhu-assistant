### 严格末手分支与审查补修

`tracking/self_terminal_evidence.py` 的新来源为 `live_self_table_terminal`。只接受当前 SELF 行动者、完整可信桌牌多重集合恰等于旧整手、可信空手、控件不是 True，且 reducer 预检证明合法出完。连续 N 个严格递增源帧绑定 round/revision/epoch、原手牌和逐槽位置；重复/倒序/坏帧/暂停/扫描/换局会中断积累并保留水位，事件置信为支持帧所有原槽分数的最小值。

审查代理发现并复现一个漏槽反例：三张牌的中间缝被局部遮挡，旧 TABLE 分割只剩两槽，固定底带也没找到漏缝。主代理将新完整性证明的候选检查扩到整个直边中段，仍使用原双角门判定；新增负例通过，绝不补造第三槽。

**边界：严格 N 帧/原槽分数只适用于新桌牌分支。** 原来可信 `self_turn=False` 的 `live_hand_diff` 路径仍独立保留其既有快捷确认语义；测试明确区分两条路径，没有宣传为所有末手都已统一严格 N 帧。

### 金色胜利与封印

原 0905-002/f1493“胜利”完整 RGB SHA 与 manifest 一致。白掩码密度仅 .03036；白色加亮金色笔画密度 .24593、两个合格宽字列、标题高比例 .82043，满足原标题结构门。亮金色分支复用已有亮度与黄色通道分离数值，继续要求原继续按钮结构和相似度 .62 的明确 victory 字形；无参考、普通黄色装饰或金色失败字形不推断胜利。
