## 已确认仍须处理的独立问题

- 两局自己的末手落到桌面后进入封印的中央 `self_turn` ROI。原图证明按钮实际消失，但新桌牌触到 ROI 下边，使当前控件检测返回 `None / entity_touches_roi_boundary`；不能简单改成 False。002 的 1484–1505 控件 ROI 像素相同，005 的 1280–1299 也持续未知。相关原 RGB 和 ROI 的 SHA 校验见 `work/video-summary/tail-self-20260907-v9/diagnosis.json` 与 `work/tail-recovery-20260907-005/result-v2.json`。
- `SceneRecognizer._observe_seat` 因按钮误切风险主动不识别自己的桌牌，目前自己的末手只有手牌差集加控件消失路径。要补直接桌面末手证据，必须先证明真实卡体、拒绝按钮白字/动画，保留实际牌点分数，并在 tracking 中按新鲜证据、手中整组一致和规则合法性提交；不能将视觉未知余牌填成 0，也不能用胜利面板倒补历史动作。
- 额外四帧原 RGB/ROI 校验与现有分割诊断位于 `work/video-summary/self-terminal-evidence-20260907-v9/geometry.json`（无模型运行）。提示按钮白字也会被标作 full_card，纸面比例甚至达到 0.6507；单用类型/白色比例不足以证明桌牌。真正末手 BJ 的候选触原 self_play 底边，不能将裁断高度当完整牌身高度计算分类裁图。
