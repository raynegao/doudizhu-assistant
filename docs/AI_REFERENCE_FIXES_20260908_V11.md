## 根因与修复

v10 的 `empty_verified = geometry.count == 0` 在实际自动路径不可达：`_infer_white_hand_count` 只返回正数或 None。模拟集成测试注入 0 掩盖了上游合同。不能直接将 None 改成 0，因为黑/白/绿色画面及极细裁边牌片也可能无候选、无原因地返回 None。

新增 `src/vision/hand_empty.py` 与 `src/config/hand_empty.py`，独立证明已标定有效手牌域的蓝色净空：

- 原几何无任何候选或错误；正数、布尔计数均拒。整个有效域的每一个像素都须满足原蓝色通道条件，不能只用整幅比例漏过 1px/3px 细条。
- 全 ROI 蓝色比例仍至少 .995。蓝色参数下界固定为 15/15/60，最小输入边长 32；显式配置只能收紧这些门，不能把近灰色 (64,64,66) 弱化成空桌布。
- 底部 UI 排除带预先固定且至多 3%，用 floor 计算，不按当前图像自动扩大。独立配置默认不排除；旧快照只有应用和完整 ROI 集合均精确匹配已测经典布局时，在内存解析为明确的 3% 兼容值。任意 ROI 改变或其它应用默认零排除，显式零优先；旧快照字节不变。
- `HandEmptyEvidence` 记录有效域、排除像素数、蓝色占比和原因，只用于专用末手分支。`HandGeometry.count=None`、视觉余牌及控件三值语义不改，不用跟踪状态补视觉 0。

支持范围必须限定：排除带应由该布局标定确认不属于合法牌身/动画位置；完全落在排除带内的小片与 GUI 装饰不可区分。因此只声称有效手牌域为空，不能声称整个 ROI、其它皮肤或任意错误标定都已证明无牌。完整桌牌、整手多重集合、连续 N 帧与 reducer 末手合法性仍是独立必需条件。

审查代理找出的两个问题均落实为负例：全局 .995 会漏窄条；可弱化的 blue 配置会接受近灰色。旧 v10 mock-zero 用例改为证明黑底即使注入 0 也不算净空，新增真实 `infer_hand_geometry → observe` 集成路径。
